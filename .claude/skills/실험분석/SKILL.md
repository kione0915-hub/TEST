# 실험분석

조건(condition)별 실험 데이터 디렉터리를 받아 데이터 품질 점검과 기초 통계를 수행하고,
**관찰(사실)** 과 **해석(추론)** 을 분리한 보고서를 `analysis/`에 저장하는 스킬.

관찰과 해석을 분리하는 이유: 관찰 문서는 누가 봐도 재현·검증 가능한 수치와 사실만 담아
이후 실험과 비교할 기준이 되고, 해석 문서는 가설과 추론을 담아 반박·수정될 수 있는
공간이 된다. 두 가지가 섞이면 나중에 어떤 문장이 데이터이고 어떤 문장이 의견인지
구분할 수 없게 된다.

## 입력

- 인자: 데이터 디렉터리 경로 (예: `data/condition_A`). 인자가 없으면 사용자에게 경로를 확인한다.
- 디렉터리 안의 `*.csv`(측정 데이터)와 `*.log` / `*.txt`(실험 로그)를 모두 대상으로 한다.
- 디렉터리가 없거나 비어 있으면 분석을 지어내지 말고, 무엇이 없는지 그대로 보고하고 멈춘다.

## 절차

1. **파일 확인** — 디렉터리의 CSV·로그 파일 목록을 확인한다. 어떤 파일이 있는지 먼저
   사용자에게 한 줄로 알린다.
2. **통계 계산** — 번들 스크립트를 실행한다 (직접 계산하지 말 것 — 수치 재현성을 위해
   스크립트가 기준이다):
   ```bash
   python .claude/skills/실험분석/scripts/analyze.py <data_dir> --json-out analysis/<condition>_stats.json
   ```
   CSV별 행 수·컬럼별 결측 수·중복 행 수·숫자 컬럼의 평균/표준편차/최소/최대,
   로그별 줄 수·ERROR/WARN 건수와 샘플이 JSON으로 나온다.
3. **로그 정독** — ERROR/WARN 샘플이 있으면 해당 로그 파일을 직접 읽어 맥락(어느 시점,
   어느 측정과 연관되는지)을 파악한다. 로그의 이상 징후가 CSV의 결측·이상값과 시간대가
   겹치는지 살핀다.
4. **보고서 작성** — `analysis/` 아래 두 파일을 만든다 (`<condition>`은 디렉터리 이름):
   - `analysis/<condition>_관찰.md` — 사실만. 수치, 파일 목록, 결측/중복 위치, 로그의
     ERROR/WARN 원문 인용. "~로 보인다", "~때문이다" 같은 추론 표현 금지.
   - `analysis/<condition>_해석.md` — 추론만. 이상값의 가능한 원인 가설, 결측 패턴의
     의미, 후속 실험 제안. 각 해석은 관찰 문서의 어느 항목에 근거하는지 명시한다.

## 보고서 형식

`<condition>_관찰.md`:

```markdown
# <condition> 관찰 결과
분석일: YYYY-MM-DD / 대상: <data_dir>

## 파일 구성
## 데이터 품질 (결측·중복)
## 기초 통계 (컬럼별 평균·표준편차·범위)
## 로그 이벤트 (ERROR/WARN 원문)
```

`<condition>_해석.md`:

```markdown
# <condition> 해석
근거: analysis/<condition>_관찰.md

## 데이터 품질 평가
## 통계적 특징에 대한 해석
## 이상 징후 가설 (각 항목에 근거 관찰 명시)
## 후속 조치 제안
```

## 마무리

- 사용자에게 핵심 발견 2–3가지를 요약해 전달한다: 데이터 품질 한 줄, 눈에 띄는 통계
  한 줄, 로그 이상 여부 한 줄.
- 저장한 파일 경로 세 개(stats.json, 관찰.md, 해석.md)를 알려준다.
